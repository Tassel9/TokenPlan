# TokenPlan 技术排障分支与示例

## 排查顺序

1. 记录错误原文、错误码、IDE/插件版本、模型和最短复现步骤。
2. 核对服务公告、登录状态、代理网络、插件配置和项目索引状态。
3. 根据 Observation 决定下一分支，一次只改变一个主要变量。
4. 最后才考虑重装插件、清理缓存、重建索引或重置配置。

## 正例

- “VS Code 插件报 401”：先确认插件版本、登录状态和完整错误原文，再匹配对应文档。
- 修改配置后要求用户复现，并记录错误是否变化，不能直接宣布修复。

## 反例

- 未确认环境就建议重装全部组件。
- 将相似错误码直接视为同一根因，或把知识库降级结果当作诊断证据。
- 技术报错同时伴随扣款问题时，由技术流程推断扣款是否成功。
