# 跨会话承接未解决咨询（2026-10-04）

用户新开会话说“上次那个账单问题”时，服务会按当前用户查找近期未解决咨询。
明确的订单号优先匹配，其次按账单、发票、退款、套餐等咨询主题筛选。
唯一匹配会读取原会话案件记录，将咨询对象、用户原话和待补充信息交给现有
上下文整理器；存在多个匹配时，先列出候选，让用户回复序号或订单号。
查不到记录或所选记录已过期时，请用户补充问题信息。

候选列表保存在当前会话的 CaseState 中，因此服务重启或进入下一轮后仍可选择。
编号对应先前显示的记录；某条记录过期不会使其编号自动指向另一条。
用户明确换话题，或改问一个完整且不匹配原候选的公共 FAQ 时，退出待选流程。
普通新问题不触发跨会话检索；当前会话已有活跃咨询时，优先沿用当前上下文。

SQLite 新增 `recent_consultations` 索引，保存用户、原会话、案件 ID、咨询对象、
意图主题、问题摘要、记录版本与更新时间。每次检索最多读取最近 20 条有效记录，
澄清最多展示 5 条；只读取同一用户、当前会话以外的记录。有效期随源 CaseState
保留时间，默认为 7 天，普通检索不续期。

索引仅收录仍有待补充字段、未解决问题、收集信息/处理阶段，或回复状态为
WAITING_USER/FAILED 的有效业务咨询。普通完整问答不自动成为未解决事项；
已解决或已进入人工请求流程的案件退出索引。

索引跟随案件在同一 SQLite 事务中更新，受现有轮次租约和提交校验保护。
跨会话承接提交成功后，按所读取的源记录版本移出旧索引，并根据新会话是否仍有
未决项决定是否继续收录，避免一个问题产生重复候选。原会话归档保持可读；
若原会话并发产生新版本，旧版本的承接不能删除新版本的索引。
旧 SQLite 文件首次加载时，会回填仍有效且未解决的案件，保留原有到期时间。

历史内容仅用于咨询连续性，不继承原案件的业务阶段、已提交材料、租约或执行结果；
订单、权益、退款进度等变化数据仍需重新查询。选择过程使用确定性的匹配规则，
不增加专门的 LLM 检索调用。真实模型的上下文整理与咨询回复仍走现有链路。

回归通过真实 SQLite 和 ChatService 验证关联、澄清、下一轮选择、重启恢复、
用户隔离、TTL、旧库回填、完整问答退出索引、并发版本保护、失效租约及事务回滚。
模型回复在测试中使用替身；这些结果不是线上效果或真实模型成功率。

验证结果：新增 23 项跨会话回归通过，完整后端测试 717 项通过；
Python 源码编译检查和 `git diff --check` 通过。
