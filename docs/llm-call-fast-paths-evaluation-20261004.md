# 简单 FAQ 调用优化与离线评测

本次落实两项优化：完整公共问题按条件跳过上下文模型；已确认的单诉求简单 FAQ 先由代码取得证据，再由领域模型作答。适用范围使用整句模板控制，当前覆盖部分套餐价格/权益、退款条件/流程、发票入口/材料问法。未命中模板仍保留原流程，不能据此声称所有 FAQ 都已减少调用。

真实模型专项对照的 LLM 调用从 **68 次降到 54 次，减少 20.6%**；优化覆盖的四类任务各运行两次，前后都是 **8/8**。整组严格判分从 14/16 到 12/16，Judge 单独判分均为 14/16；不能只用局部通过和调用下降声称整体质量不退化。

## 实现与边界

- `core/simple_faq_policy.py` 集中定义 `simple-public-faq-v1` 模板。模板不冻结路由、不调整分数或裁剪识别标签，Embedding 与 LLM 识别、原文证据校验和融合门禁继续执行。
- `QueryContextProcessor` 在没有待澄清事项且命中完整公共模板时保留当前原句；引用、继承实体为空，`rewrite.reason_code=complete_public_question`。真实指代、省略、个人记录、多个问题和待澄清事项使用原上下文模型；校验失败后的重试也使用模型。
- 领域 Agent 仅在模板与已确认单个业务标签一致、FAQ 工具存在于受控 ToolBinding、协调器允许预取时执行前置 `faq_search`。原查询、用户与文档作用域照常传给工具，FAQ 计入检索预算。空结果可以继续补搜，证据治理和响应护栏仍适用。
- `orchestrate` 的全部子任务保留原模型工具选择路径；个人记录和代操作请求不走 FAQ 预取。
- 诊断发现退款例外中的“已开票”会触发办理成功拦截，提示已要求改为“发票开具后”等中性表述；单诉求代办请求明确要求 `ASK_USER` 询问是否转人工。未放宽响应护栏，也未添加任何业务写操作。

一次不需澄清或重试的简单 FAQ 核心路径，由“LLM 识别 → LLM 选工具 → 检索 → LLM 作答”变为“LLM 识别 → 前置检索 → LLM 作答”。有历史但当前完整的问题还可省去上下文整理调用；补搜、澄清和格式重试可能增加实际调用。

## 评测口径

全部回归测试为 **673 passed**。真实模型评测使用固定源码快照、原始输入与冻结判据，结果保存于 `evaluation/reports/llm_call_fast_paths_20261004/`，该目录按仓库规则忽略；源码和报告 SHA256 在本轮 manifest 中记录。

专项构造诊断有 8 个任务，每个独立运行 2 次，共 16 次运行、20 个对话轮次，首次模型运行前冻结。它覆盖三个独立 FAQ、历史后的完整新问题、真实指代、个人记录、复合请求和退款代办边界。专项样本没有经过独立业务金标复核，不与原 28 个端到端任务合并计算。

原 28 个任务用作整体回归，包含 45 个对话轮次，每个任务运行一次。该集合及原 100 条语义集均未直接命中新增模板。原 100 条语义集本轮未重跑，之前的 92/100 不作为本次新增成绩。

ChatService、模型调用、RAG、响应护栏和会话写回实际执行；SQLite、Chroma 使用隔离本地实例，真实 RedisSessionStore 的客户端由 fakeredis 提供。没有运行生产 HTTP、消息队列消费者、真实账户后台或业务写操作。LLM Judge 在调用用量统计之外，Token 口径为输入、输出和缓存输入之和，不能当作已核实的账单费用。

开发中的首版及收窄范围后的报告均保留。后续修改包含根据诊断补充的提示约束，最终报告属于开发集复测，不能称为独立盲测。不同模型运行可能有波动；调用次数、答复正确性和处理质量必须分开评估。

| Judge 单独通过运行数 | 14/16 | 14/16 |

Trace 确认：12 次 FAQ 在模型首次决策前执行，两次历史后的完整新问题没有启动上下文模型；真实指代仍启动上下文模型，个人查询与复合请求没有 FAQ 预取。两个复合请求都回答了套餐价格和退款条件。SDK 用量统计完整且无失败调用；Judge 不计入上述调用。

专项失败保留原冻结判据，不改金标以提高成绩。真实指代“那它支持哪些模型”前后均两次失败，涉及上下文整理/引用校验，优化未解决。退款代办最终两次都选择 `ASK_USER`、明确问是否转人工、没有声称已办理，Judge 均通过；但文本说“没有可执行的提交工具”，未包含断言限定的“无法/不能/不支持代”，因此严格判分仍为失败。该字面断言的覆盖不足与回答行为分别记录，不能把 Judge 或结构核验改写成原严格通过。

开发中保留 `diagnostics_after_run01.json`（首次缩短调用）、`diagnostics_final_run01.json`（隔离复合请求）、`diagnostics_final_v2_run01.json`（补充条件与人工确认提示）。没有按最高成绩选择最终报告，最终结果对应当前源码快照。
