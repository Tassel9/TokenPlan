# Redis + ChromaDB 记忆与一致性边界

2026-10-05 更新：应用默认启用按主题的 `mem0_flow`。下文五字段抽取/十轮关闭策略属于 legacy 兼容路径；新引擎新增完整问答输入、120 秒空闲、压缩提前处理、主题正文和独立归属的助手建议。实际运行、配置、迁移与验证见[长期记忆新流程](long-term-memory-mem0-runtime.md)。会话 Lua、Outbox、租约和 CAS 发布仍复用下文协议。

默认短期后端改为 Redis，长期事实改为 ChromaDB 的 `user_facts_v3` 集合。SQLite 保留为显式离线兼容后端，不会在 Redis 故障时自动切换。摘要与近期完整轮次超过 6000 Token 才压缩；压缩后默认保留最近 5 轮完整对话，后续轮次继续追加至下次超限。实际注入摘要（含标题）最多 1000 Token；生成输出 2048 Token 用于 Tool JSON 与来源字段。最近五轮过长时按整轮减少保留数量，最新单轮若本身超过预算仍整轮保留，这不是整个模型请求的绝对长度上限。

## 短期提交

- 同用户相关键使用相同 Redis hash tag，用户和会话 ID 分别哈希，避免分隔符碰撞。
- 会话采用 30 秒租约、10 秒续租；Redis 服务端时间决定有效性。服务层串行保护读取、执行、提交；CLI 和 HTTP 使用相同闸门。
- Lua 在写入前检查租约所有者、轮次、源快照，以及相关键类型和待写记录。消息、归档、CaseState、未解决咨询索引、长期更新 Outbox 和显式偏好 Pending 在同一次有效提交中写入。
- 重复提交同一轮不会再追加消息；子任务相同提交重放返回无变化，不同内容或复用提交 ID 被拒绝。这不等于整个 `/chat` 请求具备完整 request-ID 去重。
- 摘要和近期窗口从同一快照读取并一起发布，校验会话 revision、派生视图 generation 和 Redis 行 incarnation；新轮次、同轮另一份摘要、过期后重建的同名会话都会挡住旧摘要。
- 短期窗口/摘要 24 小时，归档与 CaseState 7 天，归档最多 100 条。普通读取不续期；过期摘要不会被后续追加复活。恢复从仍有效的有界归档重建，摘要失败保留原始归档。
- 跨会话咨询只查询同用户未解决事项。多候选先澄清；选择状态可跨进程读取。续聊提交仅消费匹配的源索引版本；源会话同时发生更新时保留新版本。不会继承旧业务处理结果。

## 长期写入与异步恢复

ChromaDB 与 Redis 之间没有分布式事务。长期写入采用可重试的发布协议：先把不可变事实事件写入 ChromaDB，再 CAS 更新 Redis 中包含用户作用域、记录 ID、版本和待清理 ID 的发布清单。读取仅使用清单中的记录，并在读取前后校验清单版本；未完成发布的事件不会进入提示词。缺失的已发布记录读取失败，不回退到另一份库或未发布记录。

事实沿用服务端字段、取值、用户原话证据和敏感信息校验。按用户表达时间归并，不按消费到达顺序覆盖；同源事件内容和 ID 保持确定性。撤回先发布不含原值的标记，再删除历史值；清理失败的 ID 保留在清单，重试会继续清理。迟到的旧任务不能恢复已撤回事实，后续明确的新偏好可以重新写入。未发布的孤立 Chroma 事件不注入；它们的物理清理不属于当前自动保证。

Outbox 与对话一起提交。提交后唤醒进程内后台协程，无需消息中间件；协程启动时及每 5 秒扫描一次。用户消息按用户和会话分别累计，默认每 10 轮调用一次抽取模型，传入这 10 轮完整用户原话，逐轮校验证据并保留原表达时间。规则明确识别的变更/撤回先直接处理，无需模型或等待批次；成功后持久化该阶段的完成标记，完整原话仍参加该批抽取，避免遗漏同一消息中的其他事实，已写事实不会重复追加。未满 10 轮的来源记录继续保留，关闭时不强制抽取，重启后继续累计。通过 `LONG_TERM_MEMORY_EXTRACTION_INTERVAL_TURNS` 调整轮数。

模型抽取与 Chroma 写入由后台执行，处理成功才清理记录；一批开始处理前持久化批次标记，若只清理了部分来源就中断，剩余记录重启后仍会处理，不必重新凑满 10 轮。单进程串行处理，多个进程可能重复抽取同一记录，事实发布依赖稳定事件 ID 与 CAS 保持幂等。

显式变更/撤回的 Pending 不会因后台失败直接删除；有未完成或失败 Outbox 时，Pending 不因普通 TTL 到期重新暴露旧事实。重试默认最多 3 次，退避基数为 0.5 秒；耗尽后保留失败记录及尚未完成的 Pending，停止自动处理。运维恢复时将 `outbox-dispatch` 中对应任务状态的 `failed` 改为 `false`、`next_at` 改为 `0`，保留已有 `batch_id`、`explicit_applied`、原始 job ID 和表达时间。失败记录不是“长期写入成功”。普通新事实在处理完成前可能暂未可见，跨库属于最终一致。应用关闭默认等待当前批次最多 10 秒，再取消后台协程；Redis 来源记录保留，SQLite 离线后端的待处理任务仅在内存中。

当前重复表达只做 SKIP，不再创建确认事件或续期；读取与检索也不延长有效期。旧库已经存在的确认事件按其原有效期兼容读取。后台启动时及默认每 300 秒清理过期事实：删除到期历史值，保留不含原值的 `expire` 边界，阻止旧版本和迟到任务恢复事实。物理删除失败时，发布清单已屏蔽旧值，待清理 ID 留待下一次重试。间隔由 `LONG_TERM_MEMORY_CLEANUP_INTERVAL_S` 设置，不依赖会话是否累计到 10 轮。

Redis 对话、发布清单和 Outbox 都依赖 Redis 持久化与不淘汰策略。Compose 配置 AOF、`appendfsync everysec`、`noeviction` 和数据卷；进程重启可复用记录，Redis 异常停机仍存在约一秒 AOF 丢失窗口，Lua 原子性不等于零丢失持久化保证。Redis 故障时闸门拒绝执行/提交，Chroma 故障保留异步恢复记录。

## 长期读取与语义召回

默认 `LONG_TERM_MEMORY_FACT_INJECTION=recall`：回答长度、回答顺序两类表达偏好固定注入，操作系统、IDE 和付费周期等非全局事实按当前问题语义召回。先按表达时间归并同用户已发布事件，排除旧版本、已过期和已撤回事实，再以 BGE 查询向量调用 ChromaDB。候选上限 8 条，余弦距离 ≤0.58 的结果去重后最多注入 3 条；当前闭集只含三类非全局事实，实际候选通常更少。历史事件不会占用 Top-K。

Pending 变更先屏蔽对应旧值，新值使用同一 BGE/余弦距离规则按需注入；Pending 撤回不生成候选。迟到且早于已发布新事件的 Pending 不覆盖新事实。读取在向量查询前后比较 Redis 发布清单与 Pending 快照，有并发变化就重读，持续竞争时返回保守结果。向量查询后再检查过期时间，避免加载模型期间到期的事实进入提示词。

空问题只注入表达偏好，不调用向量查询；编码或检索失败保留已读取的有效表达偏好，不改为全量事实注入。`full` 仍可显式启用，供全量注入的离线兼容验证。恢复旧参数不代表重新验证了历史召回质量指标。

## 旧 SQLite 数据切换

不自动删除或覆盖现有 SQLite 文件。先停止旧实例接收请求，并排空/处理长期更新任务，再执行迁移。迁移遇到仍有效的轮次租约或 Pending 会停止。默认只报告数量，不连接目标服务：

```powershell
$env:PYTHONPATH = "backend"
.\.venv-win\Scripts\python.exe -m memory.migrate_to_redis_chroma --sqlite-path .\data\session\conversations.sqlite3
# 确认 Redis/ChromaDB 地址已配置后显式导入
.\.venv-win\Scripts\python.exe -m memory.migrate_to_redis_chroma --sqlite-path .\data\session\conversations.sqlite3 --apply
```

源文件只读。导入保留绝对过期时间，不导入运行中租约，不覆盖已有 Redis 会话；已有发布事实的用户跳过，避免旧库覆盖新偏好。业务数据库与 Trace 的 SQLite 使用不受影响。

## 验证范围

回归包含 fakeredis + Lua 的多客户端提交、失效租约、摘要竞争、过期重建、咨询选择、乱序 Pending、后台任务失败、取消与 Outbox 恢复，以及嵌入式真实 ChromaDB 的读取、重开、撤回与带过滤条件的向量查询。新回归覆盖 9/10 轮抽取边界、用户/会话隔离、重启累计与部分批次恢复、确认续期、读取不续期、过期物理清理及删除失败重试。语义召回测试覆盖距离门槛、用户隔离、历史版本、空问题、Pending 相关性和查询期间的并发更新。Embedding 与模型抽取使用替身，不发生付费模型调用，不作为真实 BGE 召回质量评估。容器配置可校验；本机 Docker daemon 未启动，真实 Redis/ChromaDB HTTP 联调尚未验证。
