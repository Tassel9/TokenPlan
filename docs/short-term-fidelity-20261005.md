# 短期记忆与 CaseState 修订（2026-10-05）

本次解决两种失效：压缩或下游截断使用户限制消失；任务切换和真实追问没有可靠地写入结构化状态。实现保留可追溯原文与有界恢复路径，不承诺摘要完全无损。

## 执行顺序

1. 读取同一用户、同一会话的近期窗口、摘要、任务状态与约束变更。当前用户明确的新任务会先清理任务约束，整个会话有效的条件继续保留。
2. 常见金额、期限、计费周期、禁止操作与平台要求由规则处理。现有上下文整理调用可提交其他条件的 `protected_updates`；代码要求逐字引用当前用户消息，校验类型、作用域与明确撤回措辞。假设、单次回复要求、敏感信息、业务实时状态和助手陈述不能进入保护区。
3. 判断任务延续：明确新问题和主要实体冲突优先于模型的 `resolved`；明确关联可跨意图继续。冻结 Agent 输入前重新应用任务边界和本轮已校验的约束提案，约束原文进入 `AgentContextSnapshot.constraints`。
4. 只在总量或摘要子预算超限时压缩。正常总预算 6000 Token，摘要最多 1000 Token；压缩后默认保留最近五轮完整问答，再继续累积。下游按 Token 选择完整轮次，不做用户优先、助手后补的拆分，也不截取长消息尾部。
5. Guard 处理后的 `WAITING_USER` 执行结果写入 CaseState：保存实际问题、任务 ID、来源轮次与助手来源标记。助手问题只用于流程推进，不能成为用户事实。对应执行结算后移除问题，整体完成时清理追问。
6. 有效租约下同一次提交保存完整轮次、CaseState 和约束变更。Redis 在原有 Lua/CAS 行内提交 `protected_json`；SQLite 在原事务中提交，并自动增加兼容列。摘要发布不改动保护区。

## 原文与来源

保护区按语义键保留当前值，例如 `budget`、`deadline`、`action_permission`，同时保存用户原话、作用域、来源轮次与消息标识。用户纠正时覆盖旧值，撤回时移出有效值并保留撤回原文，防止旧摘要重新引入限制。显式新任务清理任务作用域的值和撤回记录；会话作用域需要用户明确说明。

增量摘要传入上一份完整结构化 JSON，保留旧 `source_turn_seqs`。只有没有轮次的旧版纯文本允许来源 0；真实轮次不会统一退化成 0。摘要发布前检查来源集合、数字/单位/日期字面值、可识别的金额与计费周期变化、否定反转和撤回冲突。检查失败重试一次，仍失败则保留原始视图；达到 Token 触发条件后持续失败，才启用 20 条热消息兜底，按完整轮次保留。

旧记录没有保护区时，只从仍有效的原始归档重建，读取不延长保留期。已过期历史不能用于重建。旧库已经丢失且归档中不存在的条件无法凭摘要恢复。

## CaseState 的职责

CaseState 是短期记忆中的任务状态：任务实体、来源、流程阶段和待回答问题。业务阶段与提交材料仍要求原有 `CaseUpdatePayload` 证据，用户陈述和助手建议不提升为已完成业务操作。

金额、日期与禁止事项另存于同一短期会话状态，避免把 CaseState 变成所有事实的收纳容器。Task/Intent 执行状态继续由原有请求运行时管理。任务边界仍使用显式措辞、主要实体和上下文解析结果，尚未实现任意主题转换的可靠语义识别。

## 原始归档召回与保留期

用户使用“之前”“最开始”“原话”等明确回看措辞时，从同一 `(user_id, conv_id)` 的有效归档按关键词选取最多两轮完整问答，排除已在近期窗口中的轮次。整轮加入后仍需符合总 Token 预算，预算不足则不追加。没有新模型调用或向量索引；这是有界关键词恢复，模糊代词不保证命中。

默认归档保留 100 条消息、七天，分别由 `SESSION_HISTORY_MAX_MESSAGES`、`SESSION_HISTORY_TTL_SECONDS` 控制。约束变更沿用归档的逻辑 TTL，正常会话提交续期，普通读取不续期；CaseState 自身仍默认七天。约束引用可以在原始整轮已被条数淘汰后保留，但更早的完整对话无法再召回。当前用户 ID 来自调用方，沿用现有命名空间隔离，不将其描述为新增身份认证。

保护区本身或最新单轮过长时完整保留，因此 6000 Token 是正常选择预算，不是整个模型调用的硬上限。上下文提案模型、意图识别、工具证据和系统提示另有调用预算。

## 验证与边界

`tests/test_short_term_fidelity.py` 覆盖压缩条件、摘要遗漏、金额/单位/否定错误、来源继承、更正撤回、失败恢复、旧库重建、过期不复活、同会话整轮召回与用户隔离。`tests/test_memory_revision_boundaries.py` 另覆盖不同动作的权限隔离、明确放宽条件及真实业务 Agent 的上下文传递。

公开工作区的完整验证结果见[同步说明](memory-boundaries-repair-20261017.md)。测试采用临时存储、fakeredis 和模型替身，不访问已有用户库，不代表真实多轮答案准确率。模型仍可能遗漏规则未覆盖的条件，或在回答中忽略已提供的上下文；原始归档也受 TTL 与条数上限约束。
