# 短期记忆改用 SQLite（2026-10-04）

短期会话窗口与增量摘要现在直接存储并读取 SQLite。复用现有
`SESSION_DB_PATH` 和 `conversations` 表，原有 SQLite 文件无需数据搬迁；
有界原始归档、CaseState、轮次租约与提交校验继续使用同一个数据库。

窗口与摘要默认保留 24 小时，原始归档与 CaseState 默认保留 7 天。
超出 Token 预算后，移出的消息和旧摘要生成增量摘要，再通过一次事务更新
摘要与近期窗口；旧轮次不能覆盖新轮次。普通读取不延长 TTL，窗口缺失或过期
时可从仍有效的有界归档重建，重建会重新设置短期 TTL。

应用启动、CLI doctor、Compose、依赖清单与评测入口已移除 Redis 要求。
短期记忆使用 Python 标准库 `sqlite3`，长期用户事实仍由 ChromaDB 保存，
长期事实更新任务仍由 RabbitMQ 承接。

验证覆盖默认 MemoryManager 启动、文件重开后的窗口/摘要/归档/案件恢复、
旧表结构兼容、过期读取与会话隔离，以及原有 Token 预算、摘要失败、
并发恢复、旧摘要拒绝和受租约保护的一次轮次提交。

验证结果：存储与启动相关 42 项检查通过；完整后端回归 689 项通过；
`docker compose config -q`、Python 源码编译检查和 `git diff --check` 通过。
全量检查同时修正了一条仍引用旧 Embedding 依赖文件名的测试断言。

此前评测文档中记录的 Redis/fakeredis 环境属于当时版本的历史结果，
不能当作本次 SQLite 版本的模型效果证据。本次存储调整不需要重跑付费模型评测。
