# 短期摘要的 Token 预算（2026-10-04）

摘要和近期对话统一使用 DeepSeek 模型 tokenizer，按实际注入的上下文文本计数。

正常追加对话时复用已有摘要；总量超过 6000 Token 才压缩，压缩后默认保留最近 5 轮完整对话，将更早轮次与旧摘要合并重写。之后继续追加新轮次，直到再次超限。五轮限制只用于压缩后的窗口，不用于每次读取，也不会因为新增第六轮而触发摘要。

| 对象 | 默认预算 | 计数范围 |
|---|---:|---|
| 短期记忆整体 | 6000 Token | 约束原文、撤回记录、摘要、近期消息、同会话召回及其标题和角色标记 |
| 摘要自身 | 1000 Token | 渲染后的摘要及 `[短期会话摘要]` 标题 |
| 近期对话 | 剩余预算 | 压缩后默认保留最近 5 轮完整对话；为新摘要预留空间时按 1000 Token 计算 |
| 摘要生成调用 | 2048 Token | 模型返回的 Tool JSON，包括结构和来源字段 |

1000 Token 是当前摘要子预算的工程默认值，约占整体预算的六分之一，给近期原话保留更多空间。它没有被描述为通过质量或延迟对比实验得到的最优值。

参考 TaskMind 的滚动摘要流程：将旧摘要和新增历史合并重写，计算压缩后的实际 Token 量，不缩短上下文或生成失败时重试并保留原消息。TaskMind 当前还包含字段与总字符数校验；TokenPlan 在这里采用独立的摘要 Token 子预算，移除摘要总字符限制和条目的字符上限，保留结构、条数、来源与去重校验。

## 生成和发布

1. 写入一轮消息后，检查约束原文、摘要与近期对话的总 Token 量；超过 6000 Token 才压缩。摘要自身超限也执行修复；消息条数不再触发正常压缩。
2. 按摘要子预算预留空间，默认保留最近 5 轮完整对话，更早消息与旧摘要一起交给摘要模型。五轮过长时按整轮减少保留数量，不拆开用户问题和对应回答。
3. 模型重写一份摘要，只保留当前目标、已确认信息和待解决问题。
4. 用同一 tokenizer 对最终摘要计数。摘要须在 1000 Token 以内，并比其覆盖的旧摘要和消息更短；超限时执行一次更紧凑的重试。
5. 通过校验后，在配置的会话存储中原子更新摘要和近期窗口，继续校验来源版本与轮次租约。失败时保留原始记录，原始归档仍受现有消息条数与 TTL 限制。

摘要持续失败时，近期消息的兜底上限由 `SESSION_HOT_MEMORY_MAX_MESSAGES=20` 控制，用户消息和回答分别计一条，按完整轮次保留。原始归档独立保存。

生成调用的 2048 Token 给 Tool JSON 和来源字段留出空间。窗口预留和摘要长度校验都使用 1000 Token 子预算，避免把模型输出额度当成可注入摘要的大小。

2026-10-05 补充：关键约束保存用户原文与来源，不依赖摘要完整复述；增量摘要传入旧结构化 JSON，继承真实轮次而不统一改成 0。可识别的数字、单位、否定冲突和已撤回限制会拒绝发布。按需召回有效归档的完整轮次，也计入 6000 Token；保护区单独超限时保留原文。摘要仍可能漏掉未提取的重要语义，原始归档也有 TTL 与条数边界，详见[保真设计与验证](short-term-fidelity-20261005.md)。

已有摘要可能来自旧配置。读取超限摘要时会尝试重新压缩；若失败，当前请求改用预算内的有界原始归档，超限摘要留在存储中供后续重试。普通有效摘要读取不触发重写。

6000 Token 是现有压缩触发阈值与读取预算，`SHORT_TERM_RECENT_TURNS=5` 控制压缩后的保留轮数。若最新单轮本身超出预算，仍保留该轮完整内容；没有新增旧轮次且已有摘要有效时，不反复重写同一份摘要。摘要的 1000 Token 校验始终独立生效。

## 配置与验证

`SHORT_TERM_SUMMARY_TOKEN_LIMIT=1000` 控制摘要自身预算，必须为正数且小于 `SHORT_TERM_TOKEN_LIMIT`。`SHORT_TERM_SUMMARY_MAX_TOKENS=2048` 继续控制生成调用的输出上限。

回归使用真实 SQLite 与模型替身，覆盖 Token 与字符数不一致、边界超限、生成输出额度与摘要预留分离、超限重试、失败保留、旧摘要修复、归档恢复和配置校验。它验证预算契约与恢复路径，不代表真实模型的摘要质量评测。

默认存储已改回 Redis + ChromaDB，预算不变；参见[一致性说明](redis-chroma-memory-20261004.md)。
